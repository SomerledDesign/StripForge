# StripForge footprint library (`StripForge.pretty`)

Owner: Mildrew (EE). Generated by `gen_footprints.py`; don't edit the `.kicad_mod` files by hand.
Target: KiCad 10.0.4 (footprint format `20260206`, the same as the stock 10.0.4 libraries).

```sh
python3 footprints/gen_footprints.py                 # rewrites footprints/StripForge.pretty
python3 footprints/gen_footprints.py --cut-layer User.2   # if cut_marker_layer changes
```

The output is deterministic (uuid5), so a re-run with no changes gives no diff.
`tests/test_stripforge_rules.py` fails if the library is stale.

Suggested library nickname: **`StripForge`**, e.g. in a project `fp-lib-table`:

```
(lib (name "StripForge") (type "KiCad") (uri "<path to repo>/footprints/StripForge.pretty") (options "") (descr "StripForge links and cut markers"))
```

## What is (and is not) a footprint

| Family | Representation | Why |
|---|---|---|
| Strips | **Not a footprint.** B.Cu track segments, hole centre to hole centre, drawn by the writer at `strip_width_mm` | Sketch.md §4.3 / §4.7 |
| Cuts | **The B.Cu gap is the truth.** `CUT_Hole` / `CUT_Knife` are optional, pad-less *markers* | Sketch.md §4.5 |
| Wire links | `Link_P<L>` zero-ohm jumper footprints, in the schematic as `W` symbols (both pins on one net) | Sketch.md §4.4 |

## Wire links: `Link_P2.54` … `Link_P81.28` (32 footprints)

Names: `Link_P{k*2.54:.2f}` (two-decimal mm) for k = 1…32, i.e. `Link_P2.54, Link_P5.08, …,
Link_P25.40, …, Link_P78.74, Link_P81.28`. This matches the `Link_P10.16` example in
`src/stripforge/links.py` and covers Sketch.md §4.4's `Link_P5.08 … Link_P25.40` range. Kevin's
decisions (2026-09-27): keep `Link_P2.54` (adjacent strips) and extend the family to 32 pitches.
The library is 34 footprints: 32 links + 2 cut markers.

| Item | Value |
|---|---|
| Pads | `1` and `2`, `thru_hole circle`, 1.7 mm, drill 1.0 mm, layers `*.Cu *.Mask` |
| Geometry | **Vertical**: pad 1 at (0, 0) = anchor, pad 2 at (0, +k·2.54) (KiCad Y points down) |
| Placement | Anchor on hole (col, row_a) at rotation 0 puts pad 2 on (col, row_a + k). Rotation 90 puts pad 2 at +X (col + k), 270 at −X (checked with a `kicad-cli` drill export) |
| F.Fab | wire centre line pad to pad, 0.6 mm wide (≈ 23 AWG); `${REFERENCE}` and Value along the wire |
| F.SilkS | wire between the pads, 0.12 mm, kept 0.2 mm off pad copper; Reference beside the wire (rotated 90°) |
| F.CrtYd | rectangle 0.25 mm outside the pads (±1.1 mm × −1.1 … L + 1.1 mm) |
| Attributes | `through_hole` (normal part: in schematic, BOM and position files) |

Why these numbers: stripboard holes are 0.94–1.02 mm (BusBoard 0.94, Vero 1.02, generic 1.0; see
`rules/README.md`), so a 1.0 mm drill matches the physical hole. The 1.7 mm pad is KiCad's usual
pad for a 1.0 mm drill and is smaller than the strip width (1.8 mm, caliper-measured on Kevin's
X56 board, 2026-09-27), so it never reaches the next strip.

## Cut markers: `CUT_Hole`, `CUT_Knife`

| Item | `CUT_Hole` | `CUT_Knife` |
|---|---|---|
| Anchor | centre of the hole that is cut (splitter `Cut.col` integer) | midway between holes c and c+1 (splitter `Cut.col` = c + 0.5) |
| Graphic (User.1) | circle r = 1.2 mm with an ✕, 0.15 mm lines | filled bar 0.6 × 2.4 mm across the (horizontal) strip |
| Reference | on User.1, 2 mm above the anchor (use the cut id, `X1`…) | same |
| Pads | none | none |
| Attributes | `board_only exclude_from_pos_files exclude_from_bom allow_missing_courtyard` | same |

The layer is the canonical `User.1` (the board may rename it "Strip.Cuts"; footprints use the
canonical name). A marker is not electrical: if one is used, the validator must check it sits on a
real gap (Sketch.md §4.5).

## Verification done (KiCad 10.0.4, macOS)

- `kicad-cli fp upgrade` on a copy of the library: exit 0, all 34 footprints load; attributes and
  every graphic/pad survive the round trip.
- `kicad-cli fp export svg` of the library: exit 0, 34 SVGs.
- Placed on a scratch copy of the fixture board (tests/test_stripforge_rules.py): a front-side
  `Link_P5.08`, `CUT_Hole` and `CUT_Knife` add no DRC violations besides "library not in the
  library table". With a copy of Kevin's fixture project and schematic, the two cut markers add no
  schematic-parity issues (board-only works).
