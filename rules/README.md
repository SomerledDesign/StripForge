# StripForge custom DRC rules (`stripforge.kicad_dru`)

Owner: Mildrew (EE). Generated by `gen_dru.py`; don't edit the `.kicad_dru` by hand.

```sh
python3 rules/gen_dru.py                          # strip width 1.8 mm (measured on the X56 board)
python3 rules/gen_dru.py --strip-width 1.6        # another board: must equal stripboard.toml strip_width_mm
```

KiCad only reads custom rules from `<board-name>.kicad_dru` next to the board/project, so the
writer (or the user) copies this file to that name. `--strip-width` must match the width the
writer draws strips with, or rule 1 flags every strip.

**These rules are hygiene only.** Two nets on one strip, opens and link/schematic mismatches are
caught by KiCad's built-in checks (`shorting_items`, unconnected items, `--schematic-parity`),
never by a custom rule (Sketch.md §4.6).

## Rules

| # | Rule | Constraint | Why |
|---|---|---|---|
| 1 | `SF strip width` | B.Cu tracks: `track_width` min = opt = max = strip width | strips are the only B.Cu tracks; any other width is a hand-drawn track that isn't stripboard |
| 2 | `SF no F.Cu tracks` | `disallow track` on F.Cu | no component-side copper; links are `W` footprints, not tracks |
| 3 | `SF no vias` | `disallow via micro_via buried_via` | single-sided board |
| 4 | `SF no copper zones` | `disallow zone` on outer layers | the only copper is the strips; a pour would be fiction |
| 5 | `SF no back-side footprints` | `disallow footprint` on B.Cu | a part flipped to the copper side would be built mirrored |
| 6 | `SF strip and pad edge clearance` | tracks and pads: `edge_clearance` min 0.1 mm | outer holes are half a pitch in, so edge strips (0.37 mm at 1.8 mm wide) and 1.7 mm pads in edge holes (0.42 mm) break KiCad's default 0.5 mm copper-to-edge clearance; real strips run to the edge anyway |
| 7 | pad-to-neighbour-strip relaxation | commented-out template | not needed: at 1.8 mm strip width a pad up to 2.88 mm across the strip clears the next strip by 0.2 mm; the fixture's largest pad is 2.435 mm |
| 8 | dangling dead copper | note only | `track_dangling` has no `.kicad_dru` constraint; its severity is set in `.kicad_pro` (`rule_severities.track_dangling`) or allowlisted in `drc.py` |

## Verification done (KiCad 10.0.4, `kicad-cli pcb drc --format json --severity-all`)

**`kicad-cli` does not report errors in a `.kicad_dru`.** A rule file with an unknown function
(`A.isRuleArea()`, tried in a first draft) ran with exit 0 and no message, and the conditional
rules silently stopped working. So "it ran" proves nothing; `tests/test_stripforge_rules.py`
checks each rule by mutation instead:

- Unmodified scratch copy of `examples/tpi-fixture/ATtiny10_TPI_Fixture.kicad_pcb` with the rules:
  6 × `lib_footprint_issues` (the project library isn't in a library table) and 45 unconnected items
  (no strips yet), exactly the same as without the rules. No SF violations.
- Copy of Kevin's real fixture project (`.kicad_pro`, schematics, `lib/`) in `/tmp` with the rules
  and `--schematic-parity`: 0 violations, 0 parity issues, 45 unconnected.
- Mutated copy: a 0.25 mm B.Cu track, an F.Cu track, a via, a B.Cu zone and a `Link_P5.08` flipped to
  B.Cu each raise exactly the expected SF rule. Legal items (1.8 mm row-0 strip pieces, a front-side
  link, `CUT_Hole`, `CUT_Knife`) raise none.
- Without the rules the row-0 strip gives 2 × `copper_edge_clearance` (board default 0.5 mm); with
  rule 6 they are gone. Unlike clearance, the edge clearance *can* be relaxed by a custom rule.
- The dead (no-net) strip pieces raise `track_dangling` warnings with or without rules (see rule 8).

## Strip width and clearance

**Authoritative value: 1.8 mm.** Kevin measured the copper strips on his X56 board with calipers
on 2026-09-27: 1.8 mm wide, so a strip-to-strip gap of 2.54 − 1.8 = 0.74 mm. `gen_dru.py`
defaults to 1.8 mm and `stripforge.kicad_dru` is generated with it, matching
`strip_width_mm = 1.8` in the config. If a different board is used, measure it and regenerate with
`--strip-width`.

Clearance: keep KiCad's default board minimum clearance of **0.2 mm** (anything up to about 0.5 mm
works). It is well below the 0.74 mm drawn gap, and the fixture's biggest pad (2.2 mm round) still
clears the next strip by 2.54 − 1.1 − 0.9 = 0.54 mm.

### Background: published figures (research, 2026-09-27)

The X56 measurement is narrower than the published figures below, which is why the measurement,
not the literature, sets the value.

| Source | Strip width | Hole | Notes |
|---|---|---|---|
| BusBoard AN0004 "PCB Current Capacity" (ST3U StripBoard): <https://busboard.com/sites/default/files/faq/BPS-AN0004%20PCB%20Current%20Capacity.pdf> | 85 mil = 2.16 mm | – | vendor document |
| BusBoard ST1 datasheet: <https://www.busboard.com/documents/datasheets/BPS-DAT-(ST1)-Datasheet.pdf> | not stated | 0.94 mm | 1 oz copper, 1.6 mm FR4 |
| Vero (Farnell datasheet): <https://www.farnell.com/datasheets/10822.pdf> | not stated | 1.02 mm | 35 µm copper, 1.6 mm board |
| Pro-Signal "Copper Track Stripboard" 34-0410…0414: <http://static.mercateo.com/c7/a3082259b18446a7a90254737567ea01/pdf/34-0412_v01.pdf?v=1886> | not stated | 1.0 mm | 1.5 mm paper/phenolic |
| Electronics StackExchange (accepted answer): <https://electronics.stackexchange.com/questions/223702/what-is-the-current-carrying-capacity-of-a-single-stripboard-track> | 2 mm | 0.8 mm | community answer, not a vendor spec |
| nathandumont.com "Stripboard Circuit Construction": <https://nathandumont.com/blog/stripboard-circuit-construction> | "about 2 mm" | ~1 mm | hobbyist blog |

**X56 board.** "X56" matches a common generic product: *Strip Board 24 Lanes × 56 holes,
single-sided phenolic, 6.5 × 14.5 cm, 1.25 mm thick, 2.54 mm pitch*
(<https://hcess.ca/product/protobdstrip6-5x14-5-strip-board-24-lanes-x-56-holes-veroboard-like-single-sided-phenolic-6-5cm-x-14-5cm/>;
also sold as "Stripboard (small 24x56)", <https://ev-ataad.com/en/product/stripboard-small-24x56/>).
The listing gives no strip width or hole size. From its (rounded) size, the outer hole centres sit
about (145 − 55 × 2.54) / 2 ≈ 2.65 mm in from the short edges and (65 − 23 × 2.54) / 2 ≈ 3.3 mm in
from the long edges, not the half pitch (1.27 mm) that `hole_inset_mm` defaults to. That is
approximate; measure the real board.
